# Gastronomiapiva

Website for F.lli Piva Gastronomia (Rovigo, since 1960) — https://www.gastronomiapiva.com

## What this is

The `site/` folder is the deployable static site — that's the whole thing you zip up and
deploy to Cloudflare Pages (or any static host). It has no server, no framework runtime,
no build step required at deploy time.

```
site/
  index.html          the page shell (head, design-token CSS, image manifest)
  app.js              compiled app — DO NOT hand-edit, generated by `npm run build`
  src/app.jsx          the actual source: all pages, components, copy, business logic
  vendor/              self-hosted React + ReactDOM (no third-party CDN dependency)
  images/brand/        logo, storefront, team, etc.
  images/dishes/       150+ menu item photos
```

## Why it's structured this way

The site was originally handed off as a single HTML file that transpiled JSX live in the
browser via Babel (`<script type="text/babel">`). That's what was breaking on Cloudflare —
Cloudflare's deployment blocks that script type. This version pre-compiles the exact same
JSX ahead of time with Babel, so the browser only ever sees plain JS. Same design, same
behavior, same content — it just actually works when deployed.

It's a single-page app: there's one real HTML page, and "Home / Menu / Chi Siamo / Contatti
/ Ricette" are switched client-side (no separate URLs), same as the original design.

## Making changes

1. Edit `site/src/app.jsx` (this is plain JSX — components, copy, dish data, translations,
   all in one file, organized in sections with header comments).
2. Rebuild: `npm run build`
3. Preview locally: `npm run serve`, then open http://localhost:8000
4. Zip the `site/` folder and deploy it (e.g. drag-and-drop onto Cloudflare Pages, or
   connect this repo and set the build output directory to `site`).

## Known gaps

- **Rovigòto dialect toggle** works for the header/nav/hero/menu/footer copy (all present
  in the source), but the standalone dialect dictionary page it links out to
  (`rovigoto/index.html`) isn't part of this handoff and doesn't exist yet.
- **Fixed a bug from the original design**: one dish (`Polpette di Verdure`) had an invalid
  `season: 'sempre'` value that crashed the entire Menu page (`SEASONS['sempre']` doesn't
  exist). Removed the invalid season tag — dish now shows year-round with no seasonal badge,
  which was the intent.
